# Lumi v2 Setup

Lumi is a single-process Discord bot (gateway + RPC + scheduler) on Bun, PostgreSQL 18+, and Redis 8+.

## Before you start

- Discord Bot Application → [Developer Portal](https://discord.com/developers/applications)
  - Copy the bot token
  - Enable privileged intents: Server Members, Message Content, Presence
  - OAuth2 → URL Generator → scopes: `bot`, `applications.commands`
- PostgreSQL 18+ database
- Redis 8+

## Guided setup (recommended)

```bash
git clone https://github.com/lumi-devs/Lumi.git
cd Lumi
nix develop        # or install Bun 1.4.2+ and use bun directly
bun install
bun run setup
```

`bun run setup` is idempotent and safe to re-run:

- creates `.env` from scratch or updates only the keys it manages, preserving
  comments, unknown keys, and existing valid values
- prompts for `BOT_TOKEN` and `OWNER_IDS`, hiding the token as you type
- validates required URLs and fills local defaults for `DATABASE_URL`,
  `REDIS_URL`, `LOG_LEVEL`, `METRICS_PORT`, and `DEFAULT_PREFIX`
- generates `REDIS_PASSWORD` and `RPC_INTERNAL_TOKEN` when using Docker Compose
- checks Redis and PostgreSQL connectivity (offers to start local Docker
  Compose dependencies if they are not running)
- runs `prisma generate` and `prisma migrate deploy`
- writes `.env` with mode `0600` and never prints secret values

Re-run `bun run setup:check` at any time to validate configuration and
connectivity without writing files. For automation, pass values explicitly:

```bash
bun run setup --yes --token "$BOT_TOKEN" --owners "$OWNER_IDS" \
  --database-url "$DATABASE_URL" --redis-url "$REDIS_URL"
```

Run `bun run setup --help` for all options, including `--skip-migrate`,
`--skip-generate`, `--skip-checks`, `--start-deps`, `--docker`, and
`--no-docker`.

## Docker (recommended)

### Prebuilt image

```bash
cp .env.example .env
# set BOT_TOKEN, OWNER_IDS, POSTGRES_PASSWORD, REDIS_PASSWORD, RPC_INTERNAL_TOKEN
docker compose pull
docker compose --profile migrate run --rm migrate
docker compose up -d
docker logs -f lumi-bot
```

Set `LUMI_TAG` in `.env` to a release tag in production. `latest` follows the
newest stable release, not the development branch.

### Build from source

```bash
bun run setup --start-deps   # writes .env, starts Postgres/Redis, applies migrations
docker compose up -d --build # builds and starts the bot
docker logs -f lumi-bot
```

Run `bun run setup` without `--start-deps` to be prompted before Docker Compose
starts the dependencies.

`.env` must contain `BOT_TOKEN`, `OWNER_IDS`, and the Compose secrets
(`POSTGRES_PASSWORD`, `REDIS_PASSWORD`, `RPC_INTERNAL_TOKEN`). `bun run setup`
generates the secrets when they are missing. The bot process never migrates
itself; run the `migrate` service after pulling a new image.

## Nix / local

```bash
git clone https://github.com/lumi-devs/Lumi.git
cd Lumi
nix develop
bun install
bun run setup
bun run dev:bot
```

For an existing PostgreSQL and Redis, answer "no" to the Docker Compose prompt
or pass `--no-docker`, then provide their URLs when prompted.

## Ubuntu / Debian

```bash
curl -fsSL https://bun.sh/install | bash
sudo apt install -y postgresql-18 redis-server libpq-dev build-essential \
  python3 pkg-config libcairo2-dev libpango1.0-dev libjpeg-dev libgif-dev \
  librsvg2-dev libpixman-1-dev

sudo -u postgres psql <<'SQL'
CREATE USER lumi WITH PASSWORD 'lumi';
CREATE DATABASE lumi OWNER lumi;
GRANT ALL PRIVILEGES ON DATABASE lumi TO lumi;
SQL

git clone https://github.com/lumi-devs/Lumi.git
cd Lumi
bun install
bun run setup --no-docker
bun run dev:bot
```

Systemd unit example:

```ini
[Unit]
Description=Lumi Discord Bot
After=network-online.target postgresql.service redis.service
Wants=postgresql.service redis.service

[Service]
Type=simple
User=lumi
WorkingDirectory=/home/lumi/Lumi
EnvironmentFile=/home/lumi/Lumi/.env
ExecStart=/home/lumi/.bun/bin/bun run src/index.ts
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

## Arch Linux

```bash
yay -S bun
sudo pacman -S postgresql redis cairo pango libjpeg-turbo giflib librsvg pixman
sudo -u postgres initdb -D /var/lib/postgres/data
sudo systemctl enable --now postgresql redis
# create lumi user/database in postgres, then clone and run as above
```

## Windows

Use WSL2 + Docker (the Docker steps above). Native Windows Redis is not production-ready; if you must, use Memurai or run Postgres/Redis through WSL2.

## Environment variables

`bun run setup` writes these for you. The minimum local configuration is:

```env
BOT_TOKEN=your_bot_token
OWNER_IDS=123456789012345678
DATABASE_URL="postgresql://lumi:lumi@localhost:5432/lumi"
REDIS_URL="redis://localhost:6379/0"
```

Docker Compose additionally reads `REDIS_PASSWORD` and `RPC_INTERNAL_TOKEN`
(generated by setup when missing); keep `REDIS_PASSWORD` in sync with the
password in `REDIS_URL`. Other optional keys include `CACHE_NAMESPACE`,
`DEFAULT_PREFIX`, `LOG_LEVEL`, `METRICS_ENABLED`, `METRICS_PORT`, `GIT_TOKEN`,
`GIT_USERNAME`, and `WEB_BASE_URL`. See `.env.example` for the full list.

## Web dashboard (optional)

The dashboard is a separate SvelteKit service in `apps/dashboard`. It shares the
bot's Postgres and Redis instances and needs a Discord OAuth2 application plus
the bot token.

```bash
bun install
bun run db:generate
cp apps/dashboard/.env.example apps/dashboard/.env
# fill in DISCORD_CLIENT_ID, DISCORD_CLIENT_SECRET, SESSION_SECRET, BOT_TOKEN,
# DATABASE_URL, and REDIS_URL; add ${WEB_BASE_URL}/auth/callback as a redirect
# URL in the Discord developer portal

bun run dashboard:dev      # http://localhost:4173
bun run dashboard:build    # production build in apps/dashboard/build
bun run dashboard:typecheck
```

The bot must be in each managed server with Manage Roles and a role hierarchy
above the verified/pending roles if web verification is enabled. See
[agents/dashboard.md](agents/dashboard.md) for routes, the session model, and the
verification token contract.

## Verify

```bash
docker logs lumi-bot | grep "Lumi v2 is ready"
curl localhost:9090/metrics
```

Slash commands should appear in your guild after inviting the bot with the `applications.commands` scope.
