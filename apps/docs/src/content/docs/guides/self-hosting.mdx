This walks through running Lumi for yourself - a personal server, a small community, whatever. If you outgrow a single instance later (thousands of members, multiple bot processes, zero-downtime deploys), see [Production Deployment](/Lumi/guides/production-deployment/) once you've got the basics working.

## What you'll need

| Thing | Notes |
| :--- | :--- |
| [Docker](https://docs.docker.com/get-docker/) + Docker Compose | The easiest way to run Postgres and Redis. Not required - see below. |
| [Bun](https://bun.sh) `1.3.0+` | Always required, Docker or not. |
| A Discord application | Create one at the [Developer Portal](https://discord.com/developers/applications); you'll need its bot token and client ID. |

The steps below assume Docker for Postgres and Redis, since it's the fastest way in. If you'd rather not, `nix develop` gives you both without touching Docker, or you can install them yourself - Lumi just needs connection strings, it doesn't care how they got there.

## 1. Create a Discord application

1. [Developer Portal](https://discord.com/developers/applications) → **New Application**.
2. **Bot** tab → **Reset Token**, and copy it somewhere safe - you only see it once (`BOT_TOKEN`).
3. Under **Privileged Gateway Intents**, turn on **Server Members Intent** and **Message Content Intent** if you want prefix commands or anything member-related (AFK, moderation, welcome messages).
4. **OAuth2 → General**, copy the **Client ID** (`CLIENT_ID`).
5. **OAuth2 → URL Generator**: check `bot` and `applications.commands`, then whatever permissions you want the bot to have (Administrator is simplest for a personal server; scope it down for anything shared). Use the generated link to invite it.

## 2. Clone and configure

```bash
git clone https://github.com/lumi-devs/lumi.git
cd lumi
bun run setup
```

`bun run setup` walks you through building `.env`, checks your bot token against Discord, and offers to start Docker for you. Prefer doing it by hand?

```bash
cp .env.example .env
$EDITOR .env   # fill in BOT_TOKEN, CLIENT_ID at minimum - see below
```

### The variables you actually need to set

| Variable | What to set |
| :--- | :--- |
| `BOT_TOKEN` | From step 1. |
| `CLIENT_ID` | From step 1. |
| `POSTGRES_PASSWORD` | Any password. |
| `POSTGRES_URL` / `DIRECT_POSTGRES_URL` | The defaults work as-is if you kept the default password. |
| `REDIS_PASSWORD` | Any password. |

Everything else in `.env.example` already has a sensible default. The [Configuration Reference](/Lumi/configuration/) covers every variable if you need one of the advanced ones later.

## 3. Start Postgres and Redis

<Tabs>
<TabItem label="Docker (recommended)" icon="server">

```bash
docker compose up -d postgres pgbouncer redis
```

Then wait for them to report healthy:

```bash
docker compose ps
```

</TabItem>
<TabItem label="Nix" icon="setting">

```bash
nix develop
```

Gives you real Postgres and Redis running locally, no Docker needed. Point the
Postgres and Redis variables in `.env` at whatever address it prints.

</TabItem>
<TabItem label="Manual" icon="pencil">

Already run Postgres 17 and Redis 7 somewhere? Just point `.env` at them:

```bash
POSTGRES_URL=postgresql://<user>:<password>@<host>:<port>/<db>
DIRECT_POSTGRES_URL=postgresql://<user>:<password>@<host>:<port>/<db>
REDIS_URL=redis://<user>:<password>@<host>:<port>
```

</TabItem>
</Tabs>

## 4. Set up the database

```bash
bun install
bun run db:generate   # generates the database client
bun run db:migrate    # creates the tables
```

Always use `db:migrate` here, not `db:push` - it keeps a proper history, which you'll be glad of the first time you need to roll something back.

## 5. Run it

<Tabs>
<TabItem label="Docker (simplest)" icon="server">

Just runs the bot - nothing else to install.

```bash
docker compose up -d worker
docker compose logs -f worker
```

</TabItem>
<TabItem label="Bun directly" icon="bun">

Better if you're also developing - see file changes on save.

```bash
bun run dev
```

</TabItem>
</Tabs>

The bot should be online within a few seconds. Slash commands can take up to an hour to show up everywhere the first time - test in one server for faster feedback, that usually works within a minute.

## 6. Optional: the web dashboard

You don't need this - everything works from Discord. If you'd like a web UI too, it needs its own OAuth2 credentials (the same Discord application is fine) and a running bot it can talk to:

```bash title=".env" {4}
DASHBOARD_SESSION_SECRET=$(openssl rand -hex 32)
DISCORD_OAUTH2_CLIENT_ID=<same as CLIENT_ID, or a separate app>
DISCORD_OAUTH2_CLIENT_SECRET=<from the OAuth2 tab>
RPC_HTTP_URL=http://localhost:8091   # or http://worker:8091 under Docker Compose
```

Register `http://localhost:8080/api/auth/callback/discord` as a redirect under **OAuth2 → Redirects** on the Developer Portal - there's no separate redirect-URL setting to configure, it's derived from this.

<Tabs>
<TabItem label="Docker Compose" icon="docker">

```bash
docker compose --profile dashboard up -d
```

</TabItem>
<TabItem label="Bun directly" icon="bun">

```bash
bun run --cwd apps/dashboard dev          # development
# or
bun run --cwd apps/dashboard build && bun run --cwd apps/dashboard start
```

</TabItem>
</Tabs>

Visit `http://localhost:8080`. The bot needs to be running and reachable for any of it to work. More detail: [Dashboard Reference](/Lumi/dashboard/).

## 7. Optional: metrics and tracing

```bash
docker compose --profile observability up -d
```

Brings up Grafana at `http://localhost:3001` (default login `admin`/`admin` - **change the password before exposing this to the internet**), plus everything behind it. Set `OTEL_ENABLED=true` in `.env` and restart the bot to start sending traces.

## Running as a service (bare-metal)

If you're running `bun run --cwd apps/worker start` directly rather than through Docker (which already restarts on its own), keep it alive across reboots and crashes with a systemd unit:

```ini title="/etc/systemd/system/lumi-worker.service" {10}
[Unit]
Description=Lumi Discord bot worker
After=network-online.target

[Service]
Type=simple
User=lumi
WorkingDirectory=/opt/lumi
EnvironmentFile=/opt/lumi/.env
ExecStart=/usr/bin/env bun run --cwd apps/worker start
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now lumi-worker
journalctl -u lumi-worker -f   # logs
```

Run Postgres and Redis as their own services too, and point `.env` at them the same way. Running the dashboard on bare metal? Give it a matching unit with `ExecStart=/usr/bin/env bun run --cwd apps/dashboard start` (after building it once).

## Updating

```bash
git pull
bun install
bun run db:migrate
docker compose up -d --build worker   # or: bun run dev
```

Worth a quick look at the [changelog](https://github.com/lumi-devs/Lumi/blob/main/packages/core/CHANGELOG.md) or GitHub Releases first - most updates are drop-in, but anything that needs manual attention gets called out there.

## Backups

Postgres is the only thing that actually needs backing up - Redis just holds cache and queue state that rebuilds itself if lost.

```bash
docker compose exec postgres pg_dump -U lumi lumi > backup-$(date +%F).sql
```

Put this on a cron job, or use whatever snapshot mechanism your hosting platform already gives you.
