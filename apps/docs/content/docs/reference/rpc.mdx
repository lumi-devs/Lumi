The dashboard never touches Postgres, Redis, or the bot token. It posts one of <RpcCount />
actions to the worker's internal RPC server, and the worker executes it.

## Envelope

Every call carries `id`, `action`, optional `guildId` and `actorId`, an optional W3C
`traceparent` so the handler continues the caller's trace, and `data`. The contract lives in
`packages/contracts/src/rpc/router.ts`: `rpcRouter` maps each wire action string to its handler
definition — the auth requirement shown below, an input schema, and a summary. Responses are
checked with `parseRpcResponse`, which rejects malformed envelopes — the two sides deploy
independently, so the envelope is the one shape TypeScript cannot guarantee.

```json title="Request envelope"
// POST <worker>/rpc  (RPC_INTERNAL_TOKEN bearer)
{
  "id": "req-001",
  "action": "guild.config.set",
  "guildId": "123456789012345678",
  "actorId": "987654321098765432",
  "data": { "moduleName": "greeter", "key": "message", "value": "Hi!" }
}
```
