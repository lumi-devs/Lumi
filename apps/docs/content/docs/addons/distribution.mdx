---
title: Distribution
description: Register a repo, browse it, and install, uninstall, or roll back a module.
---

Distribution runs through the downloader RPC actions and the equivalent `/repo` and `/download`
commands — no shell access to the host required.

## Repos

| Command | RPC action | Description |
| :--- | :--- | :--- |
| `/repo add` | `downloader.repo.add` | Register a module repo. |
| `/repo remove` | — | Unregister a repo. |
| `/repo update` | — | Pull the repo's latest commit on its tracked branch. |
| `/repo list` | `downloader.repo.list` | List registered repos. |
| `/repo modules` | `downloader.repo.modules` | List modules a repo offers. |

A repo tracks a branch, not a pinned commit — `/repo update` deploys whatever is on that branch
at the time you run it.

## Modules

| Command | RPC action | Description |
| :--- | :--- | :--- |
| `/download install` | `downloader.module.install` | Install a module from a repo. |
| `/download uninstall` | `downloader.module.uninstall` | Uninstall a module. |
| `/download rollback` | `downloader.module.rollback` | Roll a module back to a pinned commit. |
| `/download panel` | — | Interactive install/manage panel (default subcommand). |

Installed modules are symlinked into `packages/core/src/modules/` from
`data/3rd-party-modules/` and loaded exactly like built-in ones.

## Verifying addon signatures

Lumi has no central signing infrastructure for third-party addon repos — instead it can verify
that a commit is signed by someone you've chosen to trust, using git's native SSH commit
signing. Set `ADDON_SIGNATURE_POLICY` to control enforcement:

| Value | Behavior |
| :--- | :--- |
| `off` (default) | No verification. Same behavior as before signing support existed. |
| `warn` | Unsigned or untrusted commits are allowed through, but logged and flagged in the command reply. |
| `require` | Unsigned, untrusted, or invalid signatures are rejected before the commit goes live. |

`warn`/`require` both need `ADDON_ALLOWED_SIGNERS_FILE` pointed at a git
[`allowed_signers`](https://man7.org/linux/man-pages/man1/ssh-keygen.1.html) file — one
`<principal> namespaces="git" <ssh-public-key>` line per trusted signer:

```text title="allowed_signers"
octocat namespaces="git" ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI...
```

`require` without that file set refuses to boot, so it can never silently downgrade to `off`.

Verification runs before a fetched commit goes live — a repo's HEAD after `/repo add`, the
target SHA `/repo update` is about to fast-forward to, and a pinned revision before
`/download install`/`/download rollback` create its worktree. A verified signer is stored
alongside the commit and shown in `/repo list`.

## Local development

Point the worker at out-of-tree module directories with `LUMI_DEV_PATHS` (the equivalent of
RedBot's `--cog-path`). Modules there are discovered and loaded exactly like installed ones; the
variable is env-only, non-persistent, and must never be set in production.

```bash title="Dev module paths"
LUMI_DEV_PATHS=/home/dev/my-modules:/home/dev/other-modules
```
