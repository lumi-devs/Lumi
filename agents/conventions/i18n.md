# i18n

## Only en-US exists right now

`packages/core/src/languages/` contains exactly one locale directory, `en-US/`
(9 namespace JSON files). `SupportedLanguages = ["en-US"]`
(`packages/core/src/lib/i18n/index.ts:51`), with `fallbackLng` covering
everything. Translations are managed via Crowdin (`.github/workflows/crowdin.yml`);
until other locales land, don't assume any non-`en-US` string exists.

Namespaces are wired directly in `packages/core/src/lib/i18n/index.ts:8-35`
(`LumiNamespaces` tuple at `:25-35`). There is no `lib/i18n/keys/` layer.

## What the key test enforces

`packages/core/tests/core/i18n.test.ts` (`"has no keys on disk that aren't also
in en-US"`) is one-directional: extra keys fail, missing keys are normal
in-progress work. Add a key to `en-US/commands.json` and it just works — no
other files to touch.

## Consuming a key in a command file

`packages/core/src/modules/mod/commands/kick.ts` is the reference: `kickDefFlow`
with `run: (ctx) => runModerationFlow(...)` (`kick.ts:21,92`), localized builder
via `applyLocalizedBuilder` from `@lumi/lib/i18n/index.js`
(`packages/core/src/lib/i18n/index.ts:200`, used at `ban.ts:13,105`).

- **Slash command metadata** (names/descriptions) goes through
  `applyLocalizedBuilder(builder, "commands:<key>")` on the raw
  `"namespace:key"` string — `<key>` is the base without `Name`/`Description`
  suffixes (e.g. `"commands:kick"` resolves `kickName`/`kickDescription` from
  `en-US/commands.json:55`). Never a hardcoded English string for command
  metadata.
- **Runtime reply text** goes through the bound `LumiT` translator `t(...)`
  with `"namespace:key"` strings. `fetchLanguage` (`i18n/index.ts:168-170`)
  never returns null — it falls back to `DefaultLanguage`; `null`/`undefined`
  are accepted *inputs* (`TranslationTarget`).
